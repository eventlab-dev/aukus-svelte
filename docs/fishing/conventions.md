# Соглашения

## Размер и границы

- Размер файла `.ts` делим по реальному шву (сцена/подсистема/этап,
  а не по 20 строк). Модуль крупнее 500 строк — повод посмотреть, не делает ли он
  три работы сразу; сторожа размера в репозитории нет.
- Большой класс делим по реальному шву: сцена/подсистема/этап, а не по 20 строк.
- Данные (`fish/`, `world/`, `texts`, `areas`, `config`) не импортируют UI.
- Экраны и UI импортируют `GameContext`, а не класс `Game`.
- Runtime-циклы импортов запрещены. Type-only циклы тоже лучше не заводить.

## Код

- Строгий TypeScript; `noUnusedLocals`/`noUnusedParameters` включены.
- Комментарии — по делу, на английском (как в существующем коде); пользовательские
  строки — на русском в `texts.ts`.
- Никакого мёртвого кода и «на будущее». Неиспользуемый export удаляем.
- Форматирование — Prettier с корневым `.prettierrc` (табы, одинарные кавычки, без
  точек с запятой): `npx prettier --check src/lib/minigames` проходит. Гейт качества
  здесь — `npm run check`; правки боя дополнительно проверяются игрой руками.
- Публичный API — `src/lib/minigames/fishing/engine/index.ts`. Внутренние модули не
  обещают стабильность.
- Не переименовывать id водоёмов и не менять схему прогресса без миграции.

## Документация

- Корневой `AGENTS.md`, секция 5 — короткая точка входа по игре, только необходимое
  и ссылка сюда.
- `docs/fishing/` — подробности; при изменении границ модулей обновляйте `modules.md`.
